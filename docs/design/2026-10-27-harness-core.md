# 个人助手内核与扩展边界

当前主线是可日常使用的个人助手：会话、对话循环、上下文、长期记忆、工具调度、MCP、Skill。办公连接和文档生成通过可选插件组合。此前业务试跑与简历量化材料保留为历史记录，不再作为开发前置流程。

## 核心职责与本轮修改

| 职责 | 实现与取舍 | 本轮处理 |
| --- | --- | --- |
| Session | JSONL 是追加式完整历史，SQLite 是项目、会话、运行和队列索引；会话有单写者锁 | 缓存中的会话可读取其他进程新追加的完整记录，不修剪未写完的尾行；切分支清除离开分支的来源和文件读取缓存 |
| 对话与运行 | loop 根据日志决定下一步；输入去重、插话、排队、取消和恢复由既有运行层管理 | 保留共同执行路径，插件清理失败不会阻断运行终态保存；不把办公流程加入循环 |
| 请求上下文 | 完整历史经投影形成模型输入；大结果外置、旧结果裁剪、摘要检查点逐级处理 | 新增 host context_state 快照，当前规则、记忆、Skill 版本与普通聊天分开；替换型通知只投影最新值，原记录不删除 |
| 长期记忆 | USER.md 保存用户偏好，项目 AGENTS.md/CLAUDE.md 保存项目约定；历史检索由 knowledge/recall 单独承担 | 每次模型请求前读取当前文件，更新、删除在已有会话生效；写入使用原子替换；不信任的项目不自动加载项目规则 |
| 工具 | 核心只装配基础读写、命令、搜索本地文件、待办、问答、记忆和历史检索 | Plugin 提供额外 Tool 和 services；所有工具仍经过参数校验、权限、审批、执行、持久化及输出治理 |
| MCP | 官方 SDK，stdio/Streamable HTTP，直接或延迟暴露工具 | 移除最后一个服务也会执行连接对账；串行处理连接配置变更，避免多个会话同时重建连接；保留不确定副作用不自动重放的机制 |
| Skill | 先提供目录和描述，正文按需加载 | 已加载正文更新、删除、停用会反映到下一次模型请求；压缩仍从当前 host 快照恢复正文，历史里的旧正文保留但不再作为当前指令 |

`context_state` 是 host 生成的上下文快照，不是模型自行写入的长期记忆。它参与模型输入的重建，原始聊天、工具结果和历史摘要仍是独立记录。上下文改变后，旧的供应商推理块标为 stale，沿用各协议现有兼容处理。

## 可选插件

核心运行代码不再直接导入飞书或浏览器实现。`plugins.py` 是组合边界：普通 dataclass、一个显式加载函数、标准 Python entry point。没有引入服务容器、依赖解析器、热加载或新的编排框架。

现有能力分组：

- documents：本地文档生成、格式导出、交付。
- web：网页读取和已配置的搜索服务。
- feishu：配置后提供办公工具；普通对话不会预先请求账号身份。
- browser：作为可选 MCP 服务接入，仍使用自己的浏览器租约。

“设置 → 插件”可以启停这些能力。对应连接、密钥和历史产物保留；开关在下一次运行读取。现有配置未显式写 `[plugins]` 时兼容既有能力；基础助手模式显式配置如下：

```toml
[plugins]
enabled = []
```

新插件可以作为已安装 Python 包发布入口点：

```toml
[project.entry-points."nano_workbuddy.plugins"]
notes = "my_notes:create_plugin"
```

`create_plugin(config)` 返回 `Plugin(name="notes", description="...", tools=(...))`；工具使用现有 `Tool`/`@tool` 和 Pydantic 参数类型，依赖通过 `ctx.services` 取得。也可以在嵌入场景用 `Workspace(..., extensions=(plugin,))` 注入，不需要安装包。安装和启用是独立步骤，仅启用的入口点会导入；插件加载失败时普通对话仍可运行。

Plugin 还可贡献 MCP 配置、工具包装和会话结束清理函数。Python 插件是用户安装的本机代码，不是沙箱；工具执行权限和命令隔离继续由统一 dispatcher 和现有 sandbox 负责。当前办公依赖仍随主包安装，本轮完成运行时边界与启停，没有增加插件市场或自动安装器。

## 参考 harness 的具体取舍

借鉴 DeepSeek Harness 对 session、prompt、tools、loop 的职责划分，以及工具统一进入执行管道的方式；本项目用小接口实现组合，不引入其 Cordis 插件树。[固定版本架构](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/docs/architecture.md)、[工具管道](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/docs/subsystems/tools.md)

借鉴 Pi 将原始 session 历史与压缩后的模型上下文分开的方式：追加摘要与保留边界，重建投影而不删除原记录。现有实现已经采用这一方向，本轮补上可变记忆与 Skill 的生命周期。[压缩与 session 说明](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/compaction.md)

参考 nanobot 在组装请求时明确处理当前项目、记忆、Skill 和历史摘要的方式；保持这些职责可定位，避免将长期记忆等同于聊天历史检索。[固定版本 ContextBuilder](https://github.com/HKUDS/nanobot/blob/0254bf121736bf02bbcd9e988a2c1b3fc265f8d9/nanobot/agent/context.py)

## 使用与验证

正常使用入口仍为 Web 工作台或 `uv run nwb`。本轮新增的检查围绕基础对话、插件权限与清理、同会话记忆更新、Skill 变更、跨进程会话刷新、分支缓存和 MCP 关闭，均在隔离目录执行；未启动新的模型业务试跑，也没有访问飞书业务资源。

本轮没有重写已有的 provider、权限策略、审批、沙箱、流式 UI 或日志恢复实现。当前保留单用户、单服务进程的部署边界；MCP 配置变化会停止旧连接，不提供不中断既有调用的服务热替换。后续围绕实际助手使用修复问题，按需要添加插件，不继续以重复业务试跑推进开发。
