## 试跑学到的内容

| 现象 | 归因与处理 | 对原结果的影响 |
| --- | --- | --- |
| Word 用 `2,160`，字符串 grader 要求 `2160` | 改成完整数值解析，不允许 `21600` 等错误金额蒙混通过 | 2 次离线修正为自动通过，人工 rubric 仍待评 |
| 来源冲突题需要读目录，但没有文件清单及枚举工具 | 新版公开输入文件名，禁止靠猜测文件名 | 2 次预算失败保留并标注为 harness 缺陷 |
| 合法读取工作目录被拦 | 原规则只有 `root/*`；新版加 `root` | 原 1 次严格 scope 失败保留；不是实际越界执行证据 |
| 请求只说 `updated.md`，grader 只接受根目录 | 两个 Agent 均输出在草稿同目录，属于合法解读；新版明确全路径 | 2 次离线修正，原始路径判定保留 |
| 初版目录含 B0/B1、系统提示包含物理路径 | 新版随机目录、整轮相同提示，保存系统提示 hash | 首轮不用于声称严格受控的因果收益 |
| Agent 尝试用 edit 改 Word，收到“先读取”错误而反复读取 | 产品工具反馈需继续改进；原轨迹保留，可解释额外调用 | 本轮未改动这类产品行为，也未剔除其费用/调用 |

新版代码和 v2 任务卡已有本地子进程/SDK 回归；没有把这些本地回归当成新增真实模型试跑。
下一轮应在新 run 目录重新预注册 v2 的预算与评分规则，先人工检查任务可完成性，再调用模型。

## 能与不能说明什么

这轮证明了 runner 能对真实模型保存独立 trial、工具/模型轨迹、usage 和 grader 修订，
并暴露了验收口径和环境准备缺陷。自动通过不等于事实、引用或版式已被人工认可。

每题只跑一次、服务商缓存不可由客户端清空、首轮提示包含不同物理目录，
而且本题组主要校准 spill，并未覆盖所有 prune/compact 条件。因此不计算“成本下降百分比”或宣称质量保持。
服务商实际权重 revision 未公开，保留的是请求及返回的模型 ID 和运行日期。

真实飞书、浏览器、调度、异地恢复及二轮已知权限问题尚未被这套本地材料评测验收。
24 道留出题、144 次正式业务 trial、20 类/60 次边界实验均未执行。
