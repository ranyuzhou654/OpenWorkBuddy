## 发现与修订

1. **事实数字正确还不够，单位和时点仍会错。** U1-1 把 27.42 秒与 25.247 秒的差异称为取整；U1-2 写“12 次调用”，而开发记录实际是 6 个任务、12 次 trial、94 次模型请求。来源里的“本轮真实调用为 0”也须限定到 R-C 阶段。详见 observations.json；待独立人工确认。
2. **首次调度需要合法的文件存在性检查。** 首次 read 不存在的 progress.md 产生工具错误，保守裁定把 changed 转成 unknown。首轮脚本禁用 glob，且未提供 JSON 内提到的附属证据文件；U5-1 又猜测其他路径并耗尽额度。该结果暴露受限配置下的工作流障碍，不能直接推断正常产品配置必然失败。现脚本允许仅 trial 根目录内的 glob，并明确附件可用范围；未追加实际模型重测。
3. **U6 是执行脚本配置错误。** 原脚本 scratch_dir 与 project root 相同，正确触发了产品“临时会话只检索当前会话”的边界。模型反复命中自身问题，U6-1 最终明确写“未恢复”，没有编造历史数字。现脚本分离两个目录、断言当前项目范围，并强化本地回归，必须读到旧笔记正文，而不能用本轮提问通过检查。真实模型修订后表现未验证。
4. **文献表可审计但可读性差。** 两份 Word 各 3 页、PDF 各 2 页均已逐页查看；本地 file URI 被呈现为字面 Markdown 链接，并重复长路径。另有 PDF 标题孤立在页末。原输出保留，未手动润色后冒充 Agent 结果；导出展示修复列入下一轮。

以上助手初步复核不等于用户事实验收。输入材料也经过格式转换，不能称为原生业务 PDF/Word 的自然使用样本。
