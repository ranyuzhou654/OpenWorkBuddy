## 需要校订的技术陈述

原稿“需要讨论的决策点”第一项声称缺键或多键会以 TypeError 等方式暴露。S2 展示的是下述分派模式：

```python
handler = lambda **kw: kw["command"]
```

此处用固定返回值代替实际工具执行，只验证参数接收和字典索引，不执行 shell。结果：

| 输入 | 实际结果 |
| --- | --- |
| 不传 command | KeyError，缺失键 command |
| command 为固定字符串，同时传 unexpected | 多余键被接收，返回固定字符串，未出现 TypeError |

校订稿表述为“笔记展示的分派片段未见显式 schema 校验；其中 lambda 使用 **kw 接收参数，多余键可被接收而未使用，缺少必需键时，示例中的字典索引会触发 KeyError”。这只描述所见片段，不推断底层工具或完整项目不存在其他校验。

同一段关于 OpenWorkBuddy 的建议改为先核对已有校验和结构化错误回填；当前本地 `src/nano_workbuddy/tools/registry.py` 的 `parse_args` 已调用 Pydantic `model_validate` 并捕获 `ValidationError`，不能仅凭学习笔记宣称项目缺少校验。该本地复核属于事后 Codex 辅助，没有反馈给被测 Agent。
