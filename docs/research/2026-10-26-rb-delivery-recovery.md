## 输入与调度

新 request_id 在同一应用 home 内唯一；绑定 session、正文、parent、附件 ID 与请求的 delivery。
实际从 run 路由成 steer 后，同一请求仍可重试；换会话或更改载荷返回冲突。
duplicate 返回原 input_id 和最新状态，不再只表示“曾看过此 ID”。consumed 不代表任务成功，需同时看 run_status。

旧版本有输入的请求迁移关联；只有去重记录的孤立请求可在原内容匹配时补全接收。
旧票据没有记录请求 delivery，不能追溯证明该字段；新票据严格绑定。
已 dropped/blocked/failed 的提交不会被同一 ID 静默重跑，需要以新请求明确重新执行。

手动立即运行使用独立请求 ID，即使时钟值相同也不合并。
独立新任务排在未完成任务之后，保留各自 run/request 关联；steer 仍加入当前运行。
任务页区分运行中、等待处理、等待投递。

## 结果裁定

- error、blocked、limit、cancelled 和未正常结束优先于模型报告。
- changed 要引用本轮交付文件或 confirmed 回执；文件须有通过的结构检查、保留副本及匹配 hash。
- unchanged 要有本轮成功检查引用和比较说明；工具错误、缺证据或多次报告时转为 unknown。
- 旧 run 产物不能为新 run 背书；未知结果通知“结果待核验”，不会标成“已完成”。

成功读取与比较说明只是静默的必要条件，不证明来源覆盖充分或结论正确。
结构检查与回执检查不等于事实、引用或版式验收；这些继续由 R-C 和人工评阅处理。

## 备份与恢复

先停止服务和 Agent/CLI 写者，再备份或恢复。维护需要排他 home 锁，并额外检查会话写锁。
备份先写临时归档再替换目的文件，失败不覆盖已有备份。

格式 2 保存逐文件字节数和 SHA-256、原 home、项目路径、格式与一致性说明。
恢复先校验成员路径/类型、清单、hash、SQLite 和会话结构，在 staging 中重定位已知路径后才替换目标。
默认不覆盖已有数据；force 保留原目录，安装失败回滚。替换期间进程退出时，启动根据恢复标记优先还原旧目录；
没有旧目录的新目标需重新执行 restore，不能悄悄初始化为空 home。

保留用户正文与外部项目路径，重定位会话、附件、待投递输入、规则、配置及飞书日志中的内部路径。
恢复会过期尚未执行的审批，unknown 不自动解锁；confirmed 回执仍可本地恢复，不重发。
演练同时覆盖了这两条 R-A 约束。

项目工作目录不包含在该备份内，缺失时会列出并阻止执行，应单独保存和接回项目文件。
标准密钥存储与浏览器登录 profile 仍需显式备份选项。
兼容格式 1，但标记 integrity_verified=false；旧包没有逐文件清单，不能宣称通过 checksum 核验。
