# 已交付文件后的失败恢复

已实现本地检查与下载入口：当运行在交付文件后发生错误、耗尽预算或被用户取消，界面保留原状态和文件记录。刷新后仍可点击“检查已交付版本”，核验保留副本后下载；这个入口不请求模型、不重写正文、不覆盖项目文件，也不将原运行改为成功。

这是针对 [U2-2](../2026-10-26-u2-research-r2/README.md) 所见“文件已落盘，后续模型请求超时”的产品修复。本轮只用本地模拟模型、隔离目录及一次子进程硬退出测试，没有重跑 U2 或其他收费 trial，U2-2 的原始 error 和未知费用保持不变。

## 行为与边界

- 失败后在会话日志追加持久通知，记录原始状态、错误类型、本轮当前分支上各路径最后交付的版本，以及复用这些版本的说明。旧任务的文件不算作本轮交付。
- `GET /api/sessions/{sid}/deliveries/{run_id}` 只读核验保留副本的 SHA-256，返回 available / missing / corrupt / unreadable。文件下载也检查 hash；副本缺失或损坏返回 HTTP 410，不静默重建。不同会话或不在当前分支的运行不能通过这个入口读取。
- 项目原文件已被用户修改时，下载仍来自不可变的保留版本。检查不覆盖用户工作；原有结构、引用、数字和人工验收结果继续分别呈现。
- 相同 request_id 重试返回原 error；已失败运行不会因服务重启自动调用模型。持久失败通知写入后、数据库状态提交前发生进程退出时，重启按日志对账，保留错误和已知 usage，不重新驱动模型。
- 用户显式发起新的修改或补做任务，仍是新请求。恢复通知会进入后续上下文，提醒先复用已有交付；不声称提示词能保证任意新任务永不生成新版本。
- 自动产生新通知只针对修复后的运行，不回写历史 U2-2 或其他 trial 日志。来源记录和事实/版式检查通过与否，不由下载或 hash 校验代替。

## 验证

新增 9 项故障回归，覆盖交付后 APITimeoutError、会话重开与重复请求、缺失/损坏/不可读副本、会话/分支范围、历史文件不冒充本轮交付、终态日志与数据库之间的子进程硬退出，以及预算耗尽和用户取消。恢复检查前后日志和 usage 账本不变；已知输入/输出 token 保留，失败请求仍缺响应，不填零补齐。
