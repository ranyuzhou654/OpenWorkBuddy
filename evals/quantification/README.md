# 上下文、记忆与历史检索：开发校准 v2

当前代码版本：`development-v2-tools-format`。首轮实测及其源码归档保留在 `eval-runs/quantification-2026-10-29-real/`；v2 校准只运行离线检查和确定性试跑，不改写首轮结果。

单轮预算配置：最多 12 次开发 trial，每次最多 12 次模型请求、180 秒，合计不超过 144 次请求。摘要、失败请求、收尾和重试都计数。SDK 自动重试为 0。正式任务集与 132 次正式 trial 不在本次执行范围。

## 可复跑入口

每次使用新目录；已有目录会拒绝覆盖。先运行离线检查，再选择模型运行开发集。

```sh
.venv/bin/python evals/run_quantification.py offline eval-runs/quantification-new-offline
.venv/bin/python evals/run_quantification.py pilot eval-runs/quantification-v2-new-fake --fake
# 调用真实模型；需要对应的新一轮调用授权
.venv/bin/python evals/run_quantification.py pilot eval-runs/quantification-v2-new-real --model ds-flash
```

第一次的模型连接沿用本机 opendesign / deepseek-v4.1-flash。代码仅复制被选模型的公开参数；密钥通过子进程环境传入并在读取后移除，不写入 public.json、freeze 或日志。没有联网搜索、飞书、浏览器或 MCP 调用。每次 trial 使用独立子进程、home 和随机名称的目录，不发现用户共享 Skill，不复制个人历史和记忆。两组共同工具为 read/write/edit/grep，历史任务仅 B 额外提供 recall/read_record。工具只允许读取该题声明的输入、结果和 spill，写入仅限 result.json。grep 可搜索工作区目录，但子文件仍逐个经过读取权限过滤；目录许可不等于开放所有文件。

## 开发任务与对照

| 任务 | A | B | 标准答案依据 |
|---|---|---|---|
| CTX-SPILL | 关闭三级治理 | 当前三级治理 | 大材料开头、中间、结尾的三个事实 |
| CTX-COMPACT | 关闭三级治理 | 当前三级治理 | 合成闭合历史中的约束与本地输入 |
| MEM-FRESH | 会话开始快照 | 每请求刷新 | host 更新后的 USER.md 和项目规则 |
| MEM-REUSE | 不注入已保存记忆 | 注入已保存记忆 | 两组都可读的原始说明；B 另有相同事实的记忆 |
| HIST-LOCATE | 原始说明可读 | 原始说明 + recall/read_record | 同项目历史中的最终决定 |
| HIST-VERSION | 原始说明可读 | 原始说明 + recall/read_record | 当前项目最终决定，含旧版与其它项目干扰 |

同题两组模型参数、输入、上下文窗口及预算相同；只切换表中指定机制。固定每题 A/B 或 B/A 的交错顺序，每组一次，没有显著性或泛化结论。CTX-SPILL 使用 100,000 的本地测试窗口；CTX-COMPACT 使用 32,768 的本地测试窗口。最大输出统一为 2,048；产品始终保留至少 16,384 的输出余量。窗口是压力试验设置，不代表模型原生最大窗口。

所有历史、偏好及干扰记录由 host 合成预置，不声称由 Agent 自主提炼或从自然长期使用中形成。MEM-REUSE 只测已有记忆注入的收益；MEM-FRESH 只测新值采纳，不合成一个“记忆提升率”。两项不提供历史检索，以免混淆机制。

原始输入及 gold 在父进程冻结；public.json 不含 gold。每题公开 output_contract（只含字段、类型及格式约束，不含标准答案），任务文字由同一契约生成。保存文件必须是单个 JSON 对象，禁止额外字段；金额必须为非负整数，日期为 YYYY-MM-DD，evidence 必须为单个记录 ID 或 previous-notes.txt 字符串，不能是数组或说明。评分分开保留事实正确字段数、format_valid/format_errors 和来源依据。历史依据可由实际成功的 grep/read 原文或 recall/read_record 完整相关片段支持，不强制额外读取；read_record 调用必须绑定所引用的记录 ID。自动通过不等于人类业务验收。没有期望收益阈值，不为追求数字修剪失败。

## 离线检索基准

120 条合成查询，40 条开发查询、80 条冻结测试查询；十种类型各 12 条。冻结查询与开发查询来自相同模板族，不称为独立泛化留出集。中文词、两字词、中英混合、组合条件、同义改写、版本、同名文件、选定跨项目、会话范围和无答案/排除项目分别汇报。

1,000 / 10,000 / 50,000 是索引记录数，包含消息、来源、交付文件以及背景填充记录。调用生产 Knowledge.sync 从 JSONL、内容快照入库，不绕过索引链路直接写 FTS。较大规模扩增的是无关背景记录，不能视作不同规模的真实业务语料。

Recall@5/@10、Hit@5、MRR@10 只对有答案查询计算。无答案误返回率分母仅为无答案查询。相关记录通过稳定 record_id 对照并去重。每次查询还尝试用其它项目已知 ID 调用 read_record，单独统计越权读取。这里验证的是给定授权 scope 的检索层；host 的项目范围选择另由集成回归检查。

性能记录初次构建、100 条增量更新、索引大小、每条 query 在该连接第一次查询和五次重复查询的 P50/P95。不能清空 OS 缓存，因此不称冷缓存性能；初建和增量耗时各只有一次观测。

## 指标口径

- 同一历史投影缩减率：1 - 实际模型请求序列化字符数 / 恢复原工具输出且不应用 prune/compact 的同一条历史的序列化字符数。分子分母使用同样 JSON 序列化。保留原请求、上下文检查点和工具输出存档。它是文本体积指标，不是实际 token 节省。
- 实际输入 token：使用 provider usage，累计主循环、摘要、失败后获得的响应。缓存输入包含在 input 中，不再相加；缺用量时只报可观测小计，完整值 unknown。
- 只有两组都通过且用量完整的真实模型配对，才计算实际输入 token 减少比例；提前超窗失败不作为节省资源证据。
- 工具补读、grep 调用数、摘要调用、工具错误、最终字段正确数、格式错误、原始材料未改动、日志追加性质分别保留。grep 次数不冒充读取字节，精确重复读取指标仅覆盖 read。
- 重复读取仅统计相同路径、内容 hash、offset/limit 的精确重复。不同版本不算重复；重叠区间尚不合并，不把精确重复数冒充全部冗余读量。
- 服务商价格未知，费用为 unknown。伪模型调用及 usage 仅用于验证编排，不作为成本或模型质量结果。

每个目录保存 source.zip、逐文件源码 hash、完整材料与评分规则，trial 保存 public.json、模型请求、逐调用用量、工具调用、上下文检查点、会话、最终文件及评分。异常与失败不会被自动重跑覆盖。未完成的 trial 保留 started 记录；源码变化即停止后续任务。
