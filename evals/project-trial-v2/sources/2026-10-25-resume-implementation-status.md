## 已实现机制

- 使用独立进程、home、工作目录和文件快照；Agent 只看任务与该题资料，父进程评分。
- 开发集覆盖 PDF/Word/PPT/Excel 输入、Word 及 Markdown 输出、来源冲突、未知事实、跨轮约束、本地修订。
- B0 关闭自动 spill/prune/compact，B1 启用；不修改日常产品默认值，窗口和预算检查保留。
- 单 trial 的调用计数覆盖摘要、重试和收尾；SDK 隐式重试为 0，超时真实杀掉子进程。
- 追加 trial、调用和评阅事件；保存代码 hash、数据集 hash、配置 hash、输入和输出 hash。
- 逐调用记录 raw usage、缓存 token、provider request/response ID（可得时）及实际模型名。
- 异常后仍累计已落盘 usage；恢复使用累计日志，不把后半段覆盖成整次运行用量。
- 缺失 usage/价格保留 unknown；费用计算避免将 cached input 和 reasoning output 重复相加。
- 自动结构检查、关键事实检查和人工 rubric 分开；没有人工评阅时不计成功。
- 提供盲评资料导出、人工评阅追加、按题聚类的成对 bootstrap、分组报告。

## 开发试跑发现的问题

这些是开发集的调试证据，不从分母删除，也不当成正式模型能力比较：

1. Word 数字检查只匹配 `2160`，把正确的 `2,160` 判错。已改为数值解析，保留初始判定并离线重评分。
2. 来源冲突题公开请求没有列文件名，而限定工具不提供目录枚举。新版已注入文件清单；原两次预算失败保留。
3. 初版系统提示包含物理工作目录，路径带 A/B 标签。新版整轮冻结同一份提示、使用随机无标签物理目录，有子进程回归。
4. 初版只允许 `root/*`，遗漏工作目录本身，产生一次严格 scope 检查失败。新版已补上 root，原失败标注为 harness 问题且未删除。
5. 草稿题只写“updated.md”，grader 误设为必须在根目录。校准允许输入草稿同目录的合法输出；新版任务明确全路径。
6. 6 个开发任务仍需独立人工评阅。Word 的可打开检查不等于视觉或事实验收；v2 未追加收费试跑。

首轮初始自动检查通过 5/12；有审计记录的 grader 修订后为 9/12。当前 9 次等待人工评阅、3 次保留失败，
不输出任务完成率或 pass^3。输入 619,064、输出 27,327 token；输入已包含 529,664 缓存读取 token，费用未知。
全量测试及静态检查见 [测试证据](../research/2026-10-25-eval-preparation-tests.xml)。

上一阶段验证：**249 项测试通过，0 失败、0 跳过（39.68 秒）**；`ruff check src tests evals`、
`git diff --check` 与 v2 数据/源码 freeze 校验通过。回归包括真实子进程超时 SIGKILL、
